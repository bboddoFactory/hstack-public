# 태그로 페이지 묶어 찾기

## 기대하는 결과

페이지에 태그를 달고, 태그 하나를 누르면 그 태그가 달린 페이지 목록이 보인다.

## 명세

명세 확인: 2026-11-18, 사용자 동작·완료 기준

- 사용자 동작: 페이지를 고칠 때 태그를 단다. 페이지 아래에 달린 태그가 보이고, 태그를 누르면 같은 태그의 페이지 목록으로 간다.
- 바뀌면 안 되는 것: 기존 페이지는 고치지 않아도 그대로 보인다. 처음 띄우는 절차가 늘지 않는다.
- 완료 기준:
  1. 페이지에 태그를 달고 저장하면 페이지 아래에 태그가 보인다.
  2. 태그 목록 화면에서 태그별 페이지 수와 페이지 목록을 본다.
  3. 기존 테스트가 모두 통과한다.

## 설계 후보 (아직 고르지 않음)

| | A: 별도 테이블 | B: 페이지 머리말 |
|---|---|---|
| 모양 | DB에 `PageTags(pagepath, tag)` 테이블을 두고 편집 화면에서 태그를 따로 받는다 | 마크다운 머리말에 `tags: [회의, 설계]`를 적는다. 태그 목록은 저장할 때 색인에 모은다 |
| 얻는 것 | 태그별 조회가 쿼리 하나다. 태그 이름 바꾸기가 쉽다 | 태그가 페이지 파일 안에 있어 git만으로 위키를 다시 세울 수 있다(제품 원칙 1). 이력에 태그 변경이 남는다 |
| 비용 | 페이지 파일과 DB가 따로 놀 수 있다. git만으로 복구하면 태그가 사라진다 | 태그별 조회에 색인이 필요하다. 처음 띄울 때 전체 페이지를 한 번 읽어 색인을 만든다 |
| 맞는 조건 | 페이지가 수만 개이고 태그를 자주 바꿀 때 | 페이지가 수천 개 이하이고 git 복구가 중요할 때 |

메인 권고: B. 제품 원칙 1(파일만 있으면 다시 세운다)에 맞는다. 확신 중간: 색인을 처음 만드는 시간을 아직 재지 않았다.
