# 레이어 표 틀

공통 분할 기준은 [how-we-work](../../../how-we-work.md#레이어를-나누는-공통-기준)을 따른다. [작업과 기록의 기준](../../../docs/work-records.md)에 따라 `data/story-map/<프로젝트>/tasks/<작업 이름>/레이어.md`에 두고 레이어가 끝날 때 레이어별 진행과 올린 표시를 고친다. 작업 상태는 보드 카드 하나에서만 관리하며 이 표에 별도로 두지 않는다. Review도 이 틀과 같은 기준으로 기존 표에 수정 레이어를 잇는다.

```markdown
# <작업> 레이어

- 작업: <현재 작업.md의 전체 경로>
- 현재 완료 기준: <작업 파일의 해당 부분과 지정된 상세 문서. 변경됐다면 변경 이유와 확인 기록도 연결>
- 확인 환경: <사용자가 결과를 어디서 확인하나>
- 검토 환경: <확인할 주소나 명령·브랜치. 기존 환경은 재사용>
- 배포: <작업을 닫을 때 한 번. 배포 명령·PR 병합·릴리스 등>
- 관련 설계와 결정: <작업 파일이 지정한 설계 정리와 해당 부분. 기존 자료는 실제 경로로 연결>

| 레이어 | 끝나면 보이는 모습 | 결정·남은 질문 | 레이어 진행 | 커밋 |
|---|---|---|---|---|
| 기반 | <새로 필요한 기반이나 가장 모르는 것을 얇게 확인. 기존 기반은 재사용해 불필요한 행을 만들지 않음> | <확정 결정 또는 남은 질문과 시점> | | |
| 1 | <앞선 모습에서 더하는 변화와 확인할 장면> | <확정: 기록·전제 / 질문: 무엇을 언제까지 정할지. 없으면 비움> | | |
| … | | | | |
```

확정 결정은 전제가 유지되면 다시 고르지 않는다. 미정은 그 답에 기대는 데이터·외부 약속·구현을 만들기 전에 정한다. 리뷰 레이어도 정한 방향은 연결하고 아직 답하지 않은 질문과 두 리뷰의 실제 권고를 구분한다.

옛 표의 ‘걸린 결정’ 칸은 ADR·권고의 실제 내용으로 읽고 일괄 변환하지 않는다. 메인이 완료 기준 변경을 작업 파일과 적용 문서에 먼저 맞추고 이 표에서 연결한다. 옛 핸드오프 문서는 당시 근거로 보존하며 덮어쓰지 않는다.

레이어 진행: 비어 있음 → `하는 중` → `올림, 사용자 확인 기다림` → `끝남(사용자 확인: 무엇)`. 확인을 미뤘으면 `끝남(사용자가 확인을 미룸: 무엇)`. 이것은 작업의 `todo/doing/done/cancelled` 상태와 다른 정보이며 미룬 완료 기준을 충족한 것으로 세지 않는다.
