# 시제품

무엇을 만들지 방향이 흔들릴 때, 글로 정하지 않고 만져 보고 정한다. 흔한 관행이고 이름은 버리는 시제품(throwaway prototype). 출처: Fred Brooks, "하나는 버릴 셈 치고 만들어라"(The Mythical Man-Month).

| 쓰는 때 | 쓰지 않는 때 |
|---|---|
| 최종 모습이나 방향을 모른다(어떤 형태의 제품인가, 어떤 흐름인가) | 기술적으로 되는지만 모른다 → [Understand의 실험](../understand/references/experiment-request.md) |
| 사용자가 말로 설명하기 어려운 느낌을 찾는다 | 방향은 정해졌고 만들기만 하면 된다 |

**코드는 가져오지 않는다.** 이번 질문에 답하는 데 필요한 최소 동작을 빠르게 비교하며 완성품의 구조·테스트 체계를 미리 갖추지 않는다. 선택한 방향은 실제 구현 단계에서 다시 만든다. 가져오는 것은 사용자가 써 보고 고른 **결정과 그 판단 근거**다.

## 흐름 한눈에

| 단계 | 누가 | 하는 일 | 사용자 |
|---|---|---|---|
| 1 | 메인 | 답할 질문 하나와 시제품의 갈래를 정한다 | **멈춘다.** 확인받는다 |
| 2 | 구현자 | 갈래마다 따로, 새 폴더에서 자유롭게 만든다 | 기다리는 동안 다른 일 |
| 3 | 메인 | 띄우고, 사용자가 열 수 있게 잇고, 직접 열어 본다 | |
| 4 | 사용자 | 써 보고 느낌을 말한다 | **멈춘다.** 방향을 정한다 |
| 5 | 메인 | 정한 방향과 배운 것을 남긴다 | 시제품 서버와 폴더 정리는 **승인받고** |

## 1. 질문과 갈래

[프로젝트 기준 관리](../../docs/project-guidance.md)에 따라 관련 기준과 시제품에 적용할 범위를 읽고 전달하며, 마무리에 그 문서의 Prototype 행을 확인한다.

[작업과 기록의 기준](../../docs/work-records.md)에 따라 제품 문서·보드에서 찾은 현재 작업 파일과 지정된 상세 문서를 읽는다. 위임할 때 현재 작업·적용 자료·담당 범위·자기 보고 경로를 전달하며 구현자는 작업 파일·개인 기준을 직접 고치지 않는다.

- **답할 질문은 하나.** 질문이 둘이면 시제품도 나눈다.
- **갈래는 서로 달라야 비교가 된다.** 써 보는 중에 사용자가 원하는 느낌을 말하면 그 갈래를 하나 더한다.
- 질문에 필요한 최소 동작과 실제 연결의 범위를 정한다. 가짜 데이터·응답으로 방향을 판단할 수 있으면 그것으로 비교한다. 실제 외부 응답이 판단에 필요하면 이미 합의한 범위에서 연결한다. 시제품을 자유롭게 만들라는 지시를 새 서비스 연결·비용 발생·실제 데이터 변경의 허용으로 확대하지 않는다.

## 2. 만든다

- 모델·강도·실패 시 대체와 호출 방법은 [역할표의 구현자](../../docs/agent-calls.md#구현자-레이어-구현-버리는-시제품)를 따른다. 갈래마다 따로 동시에 돌린다. 모델 배정을 이 스킬에 별도로 복제하지 않는다.
- 지시서 틀: `references/prototype-request.md`. 갈래마다 질문, 꼭 있어야 하는 것, 실행 환경을 채운다. 틀의 굵은 줄은 빼지 않는다.
- 새 지시서·보고·시제품에서 배운 근거는 `data/story-map/<프로젝트>/tasks/<작업 이름>/`에 갈래·호출별 다른 이름으로 둔다. 성공한 보고를 덮어쓰지 않는다. 버릴 코드는 위에서 정한 별도 폴더에서 만들며 코드 저장소에 개인 작업 기록을 두지 않는다. 기존 `experiments/` 자료는 당시 근거로 연결하고 옮기지 않는다.

## 3. 띄우고 열어 본다

- 메인이 띄운다. 사용자가 실제로 쓰는 곳에서 열리거나 돌아가는지 직접 확인한다.
- **사용자가 쓰는 기기나 방식의 조건으로 직접 열어 보거나 돌려 본다.** 뜨는지, 첫 동작이 되는지. 메인은 필요한 관련 코드도 확인할 수 있다. `basics.md`의 작은 수정 예외를 모두 만족하는 고침은 `how-we-work.md`의 절차로 직접 처리할 수 있다. 그 밖에 막힌 곳은 확인한 근거와 실행 결과를 구현자에게 넘겨 고치게 하고 메인이 다시 실행해 확인한다. 버리는 시제품의 일반 구현도 구현자에게 맡긴다.
- 사용자에게 여는 곳(주소나 돌릴 명령)과 각 시제품이 정한 것을 짧게 준다. "써 보며 봐 줄 것" 두세 개를 붙인다.

## 4. 써 보고 정한다

사용자가 써 보고 말한다. 정하는 것은 사용자다.

## 5. 남긴다

- 방향이 바뀌었으면 제품 문서의 목표·원칙과 "바뀐 것"을 고친다(사용자 확인).
- 작업의 목적·범위·완료 기준을 바꿔야 하면 사용자와 정한다. 별도 에픽으로 승격하거나 카드를 복제하지 않는다.
- 메인이 작업 파일에 가져올 결정·이유·현재 적용할 자료·확인 결과·남은 일을 먼저 반영한 뒤 보드 상태를 맞춘다. 보고와 현재 합의가 충돌하면 메인이 해소한다. 시제품을 확인했다는 사실만으로 제품 구현이 끝났다고 쓰지 않는다.
- 띄워 둔 시제품 서버와 폴더는 지울지 승인받는다.

**여기서 스킬이 끝난다.**
