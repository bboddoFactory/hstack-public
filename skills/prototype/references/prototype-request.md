# 지시서 틀: 버리는 시제품

[작업과 기록의 기준](../../../docs/work-records.md)에 따라 `data/story-map/<프로젝트>/tasks/<작업 이름>/시제품-<갈래>-<호출 이름>-지시서.md`로 저장한다. 보고는 같은 폴더의 `시제품-<갈래>-<호출 이름>-보고.md`다. 갈래·호출마다 다른 이름을 지정하며 성공한 보고를 덮어쓰지 않는다. 버릴 코드는 요청서에 지정한 별도 폴더에 둔다.

```markdown
# <시제품 이름> 지시서 (<날짜>)

## 읽을 것
1. 제품 문서: <전체 경로> — 먼저 끝까지 읽는다.
2. 현재 작업: <tasks/<작업 이름>/작업.md의 전체 경로>
3. 현재 적용할 상세 문서와 해당 부분: <작업 파일이 지정한 실제 경로. 먼저 만든 다른 시제품은 참고로 구분>
4. 개인 작업 기준: <Hstack의 project-guide.md 전체 경로와 시제품에도 적용할 항목·범위. 없으면 부재와 대신 읽을 근거>. 관련 팀 지침: <실제 경로>

기준과 작업 파일은 읽기만 한다. 적용한 항목·충돌·미확인·갱신 제안(없으면 없음)을 자기 보고서에 남긴다. 접근 불가도 보고하며 버릴 구현의 선택을 영구 규칙으로 만들거나 개인 안내를 고치지 않는다. 현재 합의와 상세 근거가 충돌하면 임의로 선택하지 않고 메인에게 알린다.

**원칙(들):** `/Users/<사용자>/workspace/hstack/basics.md`의 「pstack 원칙(들)」 표를 읽는다(실제 절대 경로로 적는다). 메인이 보기에 해당하는 원칙: <이름과 이번 일에서의 뜻>. 이것은 출발점이며 빠진 원칙을 더하거나 맞지 않는 것을 뺄 수 있다. 보고서에 적용한 원칙(들)과 그것이 바꾼 결정을 쓴다.

## 무엇을 하나
버리는 시제품을 만든다. 아래 질문을 사용자가 직접 판단하는 데 필요한 최소 동작을 구현한다. 완성품의 구조·테스트 체계를 미리 갖추지 않고 비교할 핵심 동작을 직접 실행해 확인한다. 코드는 실제 구현에 가져오지 않는다.

이 시제품이 답할 질문:
> <질문 하나>

꼭 있어야 하는 것:
- <몇 줄>

그 밖의 것은 **제품 문서와 합의한 범위 안에서 질문에 답할 가장 단순한 모양으로 자유롭게 정한다.** 정한 것과 이유는 보고서에 적는다. 제품 문서의 원칙과 "하지 않는 것"은 지킨다. 자유로운 구현을 새 외부 서비스 연결·비용 발생·실제 데이터 변경의 허용으로 해석하지 않는다. 추가 결정이 필요한 연결은 메인에게 알리고 이미 합의한 연결은 그 범위에서 사용한다.

## 조건
- **이 폴더(<새 폴더 전체 경로>) 안에서만** 파일을 만들고 고친다. 다른 폴더는 읽기만 한다. <본 프로젝트와 운영 경로>는 고치지 않는다.
- 이번 담당 갈래·구현 범위는 <정한 범위>다. 위 코드 폴더 외에는 아래 지정된 자기 보고서만 쓴다. 다른 에이전트도 작업 중이므로 다른 변경을 되돌리지 않는다.
- <기기와 쓰는 방식>
- 띄우는 명령 하나와, 사용자가 여는 곳(<기기·주소, 또는 돌릴 명령>)을 README에 적는다. 서버가 필요하면 `127.0.0.1:<포트>`에서 띄운다. 그곳에서 실제로 열리는지(접속 허용 설정 포함) 직접 확인한다.
- 가짜 데이터·응답으로 질문에 답할 수 있으면 그것으로 비교한다. 실제 응답이 필요해 합의한 바깥 서비스를 쓰면: <서비스·실제 호출 범위·사용할 데이터·환경 변수>. 비밀 값은 <설정 파일>을 실행 인자로 넘겨받는다. **그 파일을 열거나, 출력하거나, 복사하지 않는다. 키를 어디에도 적지 않는다.**
- 질문에 답하는 데 필요한 가장 단순한 저장 방식을 쓴다.
- 다 만들면 직접 띄우거나 돌려서 핵심 동작을 한 바퀴 확인한다. 실제 외부 호출은 합의한 범위에서만 하며 가짜 응답으로 확인한 부분과 실제 연결을 확인한 부분을 보고서에서 구분한다. 화면 도구를 못 쓰면 서버에 직접 요청해 확인하고, 못 본 것은 보고서에 적는다. 확인이 끝나면 띄운 것을 끈다.
- 커밋은 이 폴더의 git에 자유롭게 해도 된다.

## 보고서
<같은 작업 폴더의 자기 보고서 전체 경로>에 직접 쓴다. 한국어로, 코드를 모르는 사람이 읽을 수 있게:
1. 사용자가 열면 무엇을 겪는가(장면 순서대로)
2. 정한 것과 이유
3. 직접 돌려 본 일부(실제 대화나 출력)
4. 확인하지 못한 것, 써 보는 사람이 특히 느껴 봐야 할 것
5. 띄우는 명령

마지막 답은 보고서 경로 한 줄이다.
```

## 실행

갈래마다 따로 동시에 진행한다. 새 폴더를 만들고 `git init` 한 뒤 그 폴더에서 실행한다. 모델·강도·실패 시 대체·도구별 호출은 [역할표의 구현자](../../../docs/agent-calls.md#구현자-레이어-구현-버리는-시제품)를 따른다. 이 요청서에는 별도의 모델 값이나 CLI 명령 사본을 두지 않는다.
