# 출시 전 문서 기준 검토 요청서 틀

hstack 버전을 올리기 전에 이 틀로 요청서를 만들어 `data/story-map/hstack/tasks/<출시 작업>/출시검토-요청서.md`에 두고, 두 독립 검토자(Sol xhigh, Opus xhigh)에게 새 세션으로 같은 요청서를 준다. 호출 방법은 `docs/agent-calls.md`를 따른다. `<>`만 채운다.

```markdown
# 출시 전 문서 기준 검토: hstack <버전>

너는 hstack 공통 문서의 적대적 검토자다. 다른 검토자나 메인의 대화는 보지 못한다. 다른 에이전트를 호출하지 않는다. 코드와 문서는 읽기만 하고, 보고서는 `<보고서 경로>`에 직접 쓴다.

**새 규칙·문서·절·장치를 제안하지 않는다. 빼기, 합치기, 옮기기, 짧게 줄이기, 상태를 지시로 바꾸기만 제안한다.** 빠졌다고 보이는 것은 "빠짐"에 한 줄로만 적는다.

## 읽을 것 (절대 경로)

1. 제품 문서: `<hstack 루트>/data/story-map/hstack/product.md`
2. 기준: `<hstack 루트>/skills/hstack-guide/SKILL.md`의 「스킬과 규칙 문서에 쓰는 것」
3. 원칙(들): `<hstack 루트>/basics.md`의 「pstack 원칙(들)」. 해당하는 원칙: Subtract Before You Add, Laziness Protocol, Minimize Reader Load. 출발점이며 더하거나 뺄 수 있다. 보고서에 적용한 원칙(들)과 바꾼 판단을 쓴다.
4. 이번 출시의 변경: `<이전 출시 커밋>..HEAD`의 diff와 출시 작업 파일 `<경로>`
5. 검토 대상: `basics.md`, `how-we-work.md`, `README.md`, `docs/*.md`, `skills/*/SKILL.md`, `skills/*/references/*.md`, `skills/*/assets/*`, `hooks/reminder.md`, `agents/*.md`
6. 사용자와 정한 것으로 유지가 기본인 결정: <목록>. 빼자는 제안은 "사용자 결정 변경"으로 표시한다.

## 검토 질문

1. 이번 변경이 기준을 어긴 곳: 상태·경위·옛것 설명, 원본이 둘이 된 규칙, 빼지 않고 더한 것.
2. 서로 다른 말을 하는 문장.
3. 같은 뜻이 여러 곳에 있는 규칙과 원본으로 둘 한 곳.
4. 쓰이지 않는 흔적과 끝난 전환의 설명.
5. 제안마다 빼면 깨지는 것(기대는 절차·스크립트·링크).
6. 검토 대상 전체(이번 diff만이 아니다)에서 특정 사람·프로젝트의 실제 내용이 들어간 곳: 프로젝트 이름, 실제 값, 사용자 발언, 특정 PC의 경로, 직장 이야기. 고치는 쪽은 빼기나 가상 이름으로 바꾸기다.

## 보고 형식

요약과 대략의 감소량, 제안마다 위치(파일:줄)·할 일·근거·빼면 깨지는 것·우선순위·사용자 결정 변경 여부, 마지막에 빠짐·그대로 둘 것·미확인.
```
