# 변경 방향·중요한 결정의 설계 요청서

새 설계 질문과 전제가 달라진 결정에 쓴다. [작업과 기록의 기준](../../../docs/work-records.md)에 따라 `tasks/<작업 이름>/설계-<호출 이름>-요청서.md`로 저장하고 [설계자 역할표](../../../docs/agent-calls.md#설계-후보-생성)에 따라 두 새 세션에 같은 요청서를 준다. 메인의 선행 초안과 별도 적대 검토는 [Design 본문](../SKILL.md)을 따른다. 초안·설계 보고·검토 보고도 같은 작업 폴더에 호출마다 다른 이름으로 지정하고 성공한 보고를 덮어쓰지 않는다. 기존 `decisions-review/` 등의 성공 자료는 옮기거나 이름을 바꾸지 않고 실제 경로로 연결한다.

```markdown
# <주제> 설계 요청서 (<날짜>)

## 먼저 읽을 것
1. 제품 문서: <전체 경로>
2. 현재 작업과 사용자 요구·필수 동작·현재 완료 기준: <tasks/<작업 이름>/작업.md의 전체 경로와 해당 부분>
3. 현재 적용할 상세 문서·관련 이해 결과와 기존 결정: <작업 파일이 지정한 전체 경로와 해당 부분>
4. 대상 프로젝트와 이번 담당 범위: <전체 경로>
5. 개인 작업 기준: <Hstack의 project-guide.md 전체 경로와 관련 항목·적용 범위. 유지할 조건과 대안으로 바꿀 수 있는 조건. 없으면 부재와 대신 읽을 근거>. 관련 팀 지침: <실제 경로>

기준과 작업 파일은 읽기만 하고 적용한 항목·충돌·미확인·갱신 제안(없으면 없음)을 자기 보고서에 남긴다. 접근 불가도 보고한다. 기존 기준 자체가 낡았을 가능성도 근거로 판단하며 임의로 안내를 고치지 않는다. 현재 합의와 상세 근거가 충돌하면 임의로 선택하지 않고 메인에게 알린다.

**원칙(들):** `/Users/<사용자>/workspace/hstack/basics.md`의 「pstack 원칙(들)」 표를 읽는다(실제 절대 경로로 적는다). 메인이 보기에 해당하는 원칙: <이름과 이번 일에서의 뜻>. 이것은 출발점이며 빠진 원칙을 더하거나 맞지 않는 것을 뺄 수 있다. 보고서에 적용한 원칙(들)과 그것이 바꾼 결정을 쓴다.

제품 코드·운영 기록을 바꾸거나 설치·커밋하지 않는다. 비밀 값 파일은 열지 않는다. 지정 보고서 하나만 직접 쓴다. 다른 설계 보고와 메인의 초안을 보지 않는다. 추가 에이전트를 부르지 않는다.

## 질문과 비교 기준
<왜 지금 이 결정이 필요한가. 현재 범위·변경 비용·비교할 질문>

### 확정 (다시 열지 않는다)
<사용자 목적·지킬 조건, 이미 같은 높이의 대안과 비교를 거친 결정만>

### 후보 수단 (아직 같은 높이의 대안과 비교되지 않았다)
<대화·실험에서 나온 "어떻게". 확정 전제로 쓰지 말고 비교 대상으로 다룬다. 없으면 없다고 적는다>

먼저 전제를 꺼낸다. 위 후보 수단과 설계를 복잡하게 만들 것 같은 전제를 적고, 각각 같은 높이의 대안을 적어 비교한다. 비교에 필요한 사실을 싸게 시험할 수 있으면 시험 방법(무엇을 실행해 무엇을 보면 결정이 바뀌는지)을 적는다.

<허용된 실행과 비용 한도. 없으면 읽기만 한다>

요구에 맞는 가장 단순한 구조를 먼저 제안한다. 주요 책임·상태 소유와 수명·데이터 흐름·중요한 실패 처리·기존 구조와의 연결을 설명한다. 실제 선택이 갈리는 대안만 비교하며 후보 수를 채우지 않는다. 더하거나 나누면 무엇이 달라져야 하는지 이유를 적는다.

설계 질문과 예시는 <docs/design-principles-reference.md의 전체 경로>에서 조건에 맞는 부분만 참고하고 판단에 쓴 이유와 한계를 설명한다. 필수 조건 충족 여부, 얻는 것·감수하는 비용·선택이 바뀌는 조건, 지금 정할 것과 레이어에서 구체화할 것을 구분한다.

‘나중에 바꾸면 비싸다’면 어떤 데이터가 쌓이거나 어떤 외부 호출자·구현을 다시 바꿔야 하는지 적는다. 기술 스택·저장 데이터·공개 규격·이미 보낸 것·정책과 계약 중 실제 해당하는 것을 본다. 모든 기반 항목을 새 기능으로 추가하지 않는다.

‘보통 이렇게 한다’는 말에는 표준·출처 있는 관행·자신의 의견을 구분한다. 아직 아무도 말하지 않았지만 이번 판단에 필요한 것을 최대 세 개 적고, 없으면 없다고 한다.

## 보고
<각 보고서의 전체 경로. 각자 자기 보고서만 다룬다>
쉬운 한국어로 결론·이유·후보 차이·확인 근거·미확인을 적는다. 읽기로 판단한 것과 실행한 결과를 구분한다. 제품 방향을 사용자 대신 확정하지 않는다.
```

실행과 출력 저장·모델 확인·실패 시 대체는 [공통 호출](../../../docs/agent-calls.md)을 따른다. 메인은 선행 초안과 두 보고를 같은 기준으로 비교하고 Design의 독립 적대 검토와 사용자 선택을 연결한다. 다수결이나 보고 일치를 실제 검증으로 대신하지 않는다.
