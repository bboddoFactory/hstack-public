# 이론 모음

화면의 목적에 맞는 원칙을 고를 때 펴 본다. 사용자에게 설명할 때는 이름, 짧은 뜻, 출처와 구분(업계 표준 / 흔한 관행 / 내 의견), 이 화면에 맞는 이유를 붙인다. 새 이론을 쓰면 여기에 더한다.

## 색

| 이론 | 뜻 | 답하는 질문 | 출처와 구분 |
|---|---|---|---|
| 60-30-10 규칙 | 화면의 60%는 바탕, 30%는 글자·면, 10%만 강조색 | 색을 얼마나 쓰나 | 인테리어에서 온 흔한 관행 |
| 회색 + 강조색 하나 | 화면 대부분은 무채색, 강조색은 하나만 아껴 쓰고 경고색은 작은 곳에만 | 색을 몇 개 쓰나 | Refactoring UI(Wathan·Schoger), 흔한 관행 |
| 색상환 조화 | 보색(마주 보는 색), 유사색(이웃한 색) 등으로 어울리는 색을 고른다 | 어떤 색끼리 어울리나. 양은 답하지 않는다 | Itten 색채론, 흔한 관행 |
| 톤 팔레트 | 씨앗 색 하나에서 밝기 단계(톤)를 만들어 역할에 배정한다 | 한 색에서 여러 단계를 어떻게 얻나 | Material Design 3, 업계 표준(그 플랫폼) |
| primitive·semantic token | primitive token(단계 색)과 semantic token(바탕·면·글자·강조)을 나누고 화면은 semantic token만 부른다 | 값을 어디에 어떻게 담나 | Design Tokens(W3C 커뮤니티 그룹 초안), 흔한 관행 |

## 다크 모드

역할은 같고 값만 바꾼다. 출처: Material Design 다크 테마 가이드, Apple HIG Dark Mode(업계 표준).

- 바탕은 검정 대신 짙은 회색. 순수 검정은 대비가 너무 세고 그림자가 보이지 않는다.
- 면은 다크에서 바탕보다 밝게. 라이트에서 그림자로 보이던 높이를 밝기로 보인다.
- 글자는 완전한 흰색보다 낮게. 눈부심을 줄인다.
- 강조색은 같은 계열의 밝고 덜 진한 톤. 짙은 바탕에서 진한 색은 번져 보인다.
- 대비 4.5:1을 다크에서 따로 다시 잰다.
- 기기 설정(`prefers-color-scheme`)을 따르고 `<meta name="color-scheme" content="light dark">`를 둔다.

## 글자

| 이론 | 뜻 | 출처와 구분 |
|---|---|---|
| 타입 스케일 | 본문 크기에서 일정한 비율(1.2, 1.25, 1.333 …)로 단계를 만들고 그 단계만 쓴다 | Tim Brown "More Meaningful Typography"(2011), 흔한 관행 |
| 시각적 위계 | 크기·굵기·색·위치로 무엇을 먼저 볼지 정한다. 가장 큰 것이 핵심 | NN/g "Visual Hierarchy", 흔한 관행 |
| 고정폭 숫자 | 숫자의 폭을 같게 해 줄지어 볼 때 자릿수가 맞는다 | OpenType `tnum`, CSS `font-variant-numeric: tabular-nums`, 업계 표준 |
| 기기 기본 글꼴 | 웹폰트 대신 기기 글꼴. 빨리 뜨고 외부 요청이 없다 | Apple HIG, 흔한 관행 |
