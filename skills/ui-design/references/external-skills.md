# 외부 스킬 참고

근거 등급: 측정(비교 결과 있음) / 사례(시연뿐) / 주장.

외부 스킬 대부분은 에이전트가 좋은 취향을 갖게 하려는 것이다. 우리는 언제 멈춰서 사용자가 고르게 할지를 정하고, 에이전트에게는 원칙과 기본 점검을 맡긴다. 새 스킬을 보면 아래 표에 한 줄 더하고, 큰 묶음은 들이지 않는다.

| 이름(근거) | 그쪽의 생각 | 가져온 것 / 들이지 않은 이유 |
|---|---|---|
| Anthropic frontend-design(사례) | 브리프마다 고유한 정체성, 과감함은 한 곳에만 | 주제·사용자·실제 내용에서 출발하는 것은 같다. 정체성은 에이전트가 아니라 사용자가 비교판으로 고른다 |
| Impeccable(사례) | AI 흔적 목록, distill·quieter·bolder·audit 명령, 검출 규칙 | 화면 확인 때 "덜어내기·조용하게"라는 어휘만. 별도 PRODUCT.md·DESIGN.md 체계는 우리 기록과 겹쳐 들이지 않는다 |
| taste-skill(측정, 제작자 자체) | 방향 20개 중 3개 배정, 폭 셋 확인, 스크린샷 보고 고침 | 비교판과 폰 폭 확인. 금지 규칙 위반 0이어도 스킬 없는 쪽보다 낮았다는 경고 |
| Emil Kowalski(주장) | 에이전트는 취향이 없다. 자주 보는 동작은 애니메이션을 줄인다 | 기본 점검표의 "움직임은 기본 없음" |
| Vercel 웹 인터페이스 가이드라인(주장, 일부 접근성 표준) | 키보드·초점·상태·입력·폰의 누락 검사 | 기본 점검표의 출처. 입력·폼 컴포넌트가 처음 생길 때 펴 본다 |
| baseline-ui(주장) | 요청 없는 애니메이션 금지, 기존 체계 우선 | "고르지 않은 값 없음"과 같은 방향. Tailwind·React 전제는 가져오지 않는다 |
| UI/UX Pro Max(주장) | 업종별 스타일·팔레트 자료집에서 검색 | 들이지 않는다. 업종별 기본값은 또 다른 기본값이다 |
| Stitch design-md(주장) | 기존 화면에서 규칙을 뽑아 DESIGN.md로 | 화면이 이미 있는 앱의 테마 정하기 출발점. 우연히 생긴 값도 옮겨지니 "누가 골랐나"를 하나씩 확인한다 |
| OpenAI 프런트엔드 글(사례·주장) | 디자인 시스템 먼저, 강조색 하나·서체 둘 같은 강한 제약 | 테마를 먼저 정하는 것은 같다. 숫자 제약은 우리 원칙(60-30-10 등)으로 대신한다 |
| Stageshow, Benji Taylor(사례) | 한 문장 철학, anti-pattern에 이름, 좋은·나쁜 예 나란히, 찍어 보고 고침, with/without 비교 | 이 스킬의 한 문장, anti-pattern 모음 |
| 구조가 다른 안을 나란히(측정, Dow 2010·Tohidi 2006) | 하나만 보면 후하게, 여럿을 함께 봐야 비교 | 비교판의 근거 |
| 방향을 모델 밖에서(측정, Impeccable 자체 소규모) | 모델에게 고르게 하면 30번 중 27번 같은 안 | 고르는 사람은 사용자. 절차가 길면 지친다 |
| 참고 이미지에서 출발(측정, CHI 2024) | 처음 본 예시에 생각이 묶인다 | 참고 앱은 이유를 보는 데만, 겉모양을 베끼지 않는다 |
| SkillsBench(측정, 디자인 과제 아님) | 좁은 스킬이 큰 묶음보다 나았다 | 외부 스킬을 여러 개 깔지 않고 우리 것도 작게 둔다 |
