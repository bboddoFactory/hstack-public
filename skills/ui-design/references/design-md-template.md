# DESIGN.md 틀

`~/workspace/hstack/data/story-map/<프로젝트>/DESIGN.md`에 둔다. 저장소에 팀의 디자인 문서가 있으면 만들지 않는다.

값마다 "어느 목적을 위해, 어느 원칙으로"를 붙인다. 사용자가 고른 값과 임시 값을 구분한다. 처음부터 모든 절을 채우지 않는다. 정한 것만 쓰고, 새 컴포넌트가 생기면 그때 절을 더한다.

```markdown
# DESIGN

<무슨 화면들의 시각 규칙인가 한 줄>. <언제 누가 무엇을 보고 골랐나>.
여기 없는 색이나 글자 크기는 쓰지 않는다. 새로 필요하면 이 문서에 이유와 함께 먼저 더한다.

## 색

원칙: <예: 60-30-10, 회색 + 강조색 하나(출처)>. <이 앱에 왜>.

| 역할 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| 바탕 | | | |
| 면 | | | |
| 선 | | | |
| 글자 | | | |
| 보조 글자 | | | |
| 강조 | | | <어디에만> |

- 다크: <기기 설정을 따르나, 원칙>
- 대비: <4.5:1 확인 범위>
- 아직 없는 것: <정했지만 아직 안 쓰는 값과 쓸 때>

## 글자

- 글꼴: <무엇, 이유>
- 크기: <스케일과 쓰는 단계>
- 숫자: <고정폭 여부>

| 단계 | 쓰는 곳 |
|---|---|

## 화면별

### <화면 이름>
- 핵심: <이 화면에서 가장 먼저 봐야 할 것, 사용자가 고름>
- 위에서 아래로: <배치>
- <이 화면만의 규칙과 이유>

## 컴포넌트

### <컴포넌트 이름> (<처음 생긴 작업>, <고름 / 임시>)
- <모양, 상태별 표시, 이유>

## 쓰지 않는 것
- <예: 카드 상자, 이모지>
```
