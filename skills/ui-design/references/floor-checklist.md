# 기본 점검표

사용자에게 묻지 않고 매번 지키는 것. 사용자가 모르는 줄도 모르는 것을 여기서 막는다. 화면 작업에 들어갈 때, 비교판을 낼 때, 화면을 확인할 때 펴 보고, 이번 화면에 걸리는 것을 최대 셋 꺼낸다. 겪을 때마다 한 줄씩 더한다.

| 영역 | 지키는 것 | 출처와 구분 |
|---|---|---|
| 대비 | 글자는 라이트·다크 모두 바탕과 면 위에서 4.5:1 이상. 큰 글자는 3:1 | WCAG 2.x 1.4.3, 업계 표준 |
| 색만으로 알리지 않기 | 경고·상태는 색과 함께 글자나 모양으로도 | WCAG 1.4.1, 업계 표준 |
| 누를 곳 크기 | 폰에서 44pt 이상 | Apple HIG, 업계 표준 |
| 키보드 초점 | 초점이 보인다. 지우지 않는다 | WCAG 2.4.7, 업계 표준 |
| 화면 폭 | 폰 폭(375px)에서 넘치거나 겹치지 않는다. 넓은 화면은 같은 일을 더 넓게 | 흔한 관행(반응형 웹) |
| 실제 데이터 | 가짜 숫자 대신 실제 금액·긴 이름으로 본다. 한국어 낱말이 중간에서 끊기지 않는다 | 겪은 일 |
| 상태 | 불러오는 중·비어 있음·실패가 각각 무엇을 보여 주는지. 0원과 "없음"을 헷갈리지 않게 | 흔한 관행(Vercel 웹 인터페이스 가이드라인) |
| 다크 모드 | 기기 설정이 다크일 때 무엇이 뜨는지 정했다. 정하지 않았으면 라이트만이라고 명시한다(`color-scheme`) | 겪은 일 |
| 숫자 | 줄지어 비교하는 숫자는 고정폭 | OpenType `tnum`, 흔한 관행 |
| 움직임 | 기본은 없음. 자주 쓰는 동작일수록 두지 않는다. 두면 `prefers-reduced-motion`을 따른다 | Emil Kowalski(주장), WCAG 2.3.3 |
| 고르지 않은 값 | DESIGN.md에 없는 색·크기·간격이 끼지 않았다. 가능하면 테스트로 검사 | 우리 진단(아무도 고르지 않은 기본값) |
| 강조색의 양 | 강조색과 경고색이 화면을 차지하지 않는다. 경고는 작은 곳에만 | 60-30-10, Refactoring UI |
