# Codex 자동화 (파일로 다루기)

앱이 업데이트되면 달라질 수 있으니 이상하면 아래 "확인하는 법"으로 다시 본다.

**실제 일을 하는 기존 자동화의 주기·권한·상태는 사용자가 요청하지 않으면 바꾸지 않는다.** 새로 만들 때는 먼저 시험 prompt로 확인한 뒤 실제 prompt로 바꾼다.

## 자동화 하나 = 폴더 하나

`~/.codex/automations/<id>/automation.toml`. 폴더 이름과 파일 안의 `id`가 같아야 한다. 앱은 파일을 읽어 자기 DB(`~/.codex/sqlite/codex-dev.db`의 `automations` table)에 넣는다. **실행은 DB를 보고 한다.**

| 필드 | 뜻 |
|---|---|
| `version = 1`, `id`, `name` | 식별. `id`는 폴더 이름과 같게 |
| `kind` | `cron`: 정해진 시각에 프로젝트 폴더 기준으로 새 대화를 연다. `heartbeat`: 이미 있는 대화(`target_thread_id`)에 새 턴을 붙인다 |
| `prompt` | 실행할 때 받는 지시문. **없으면 파일이 조용히 무시된다** |
| `status` | `ACTIVE` / `PAUSED` |
| `rrule` | 반복 규칙. 예 `FREQ=DAILY;BYHOUR=8;BYMINUTE=0;BYSECOND=0`. **없으면 24시간마다 도는 기본값으로 들어간다** |
| `cwds` | 작업 폴더 목록(cron). 없는 폴더를 써도 막히지 않고 돈다 |
| `target_thread_id` | heartbeat가 깨울 대화 |
| `model`, `reasoning_effort`, `execution_environment` | 선택. 쓰지 못하는 모델(예 `gpt-5.5`)은 다른 모델로 바뀌어 돈다 |

cron과 heartbeat 중 고르는 기준: 이전 대화의 맥락이나 승인 이력을 이어 써야 하면 heartbeat, 매번 빈 대화로 시작해도 되면 cron.

## 만드는 순서

1. 비슷한 기존 파일을 복사해서 `id`, `name`, `prompt`, `rrule`을 바꾼다. 처음엔 prompt를 "테스트라고만 보고"로 둔다.
2. 폴더와 파일을 만든다. 상태는 `PAUSED`로 시작하는 것을 권한다(바로 `ACTIVE`로 만들어도 만든 순간에는 돌지 않는다).
3. **15~30초 안에 앱 DB에 row가 생겼는지 본다.** 없으면 무시된 것이다(아래 실수 목록).
4. `ACTIVE`로 바꾸고 예약 시각 ±5분 뒤에 대화가 생겼는지 본다.
5. 잘 돌면 실제 prompt로 바꾼다. prompt와 rrule 수정은 다음 실행에 반영된다.

## 조용히 틀리는 곳

앱은 잘못된 파일에 경고를 내지 않는다. 아래는 모두 흔적 없이 무시되거나 엉뚱하게 도는 경우다.

- `prompt` 줄이 없다: 무시된다
- toml 문법이 깨졌다(따옴표 미닫음 등): 무시된다
- 파일 안 `id`가 폴더 이름과 다르다: 무시된다(고쳐 쓰면 들어온다)
- `rrule` 줄이 없다: 무시되지 않고 24시간마다 도는 자동화가 조용히 생긴다

## 예약 시각

- 자동화마다 예약 시각이 −300~+300초 흔들린다. 같은 id와 같은 시각이면 같은 값이다. "일찍 도는 일"도 이것이다.
- 실제 실행은 계산된 시각 직후 30초 틱(매분 :19초, :49초)에 일어난다.
- 정각에 시작해야 하는 일에는 쓰지 않는다. 몇 분 일찍 돌아도 되게 prompt를 짠다(예: 오늘 날짜를 prompt에서 계산하지 말고 실행 시점에 읽게 한다).
- 앱 코드를 읽어 안 규칙이다. 이 규칙에 기대는 자동화는 아래 「시험하는 법」으로 먼저 확인한다. 분이 하나인 DAILY·HOURLY·WEEKLY는 ±300초, 분이 여럿이면 ±119초, 초가 여럿이거나 `MINUTELY;INTERVAL<60`이면 흔들림이 없다.

## 고치기와 멈추기와 지우기

- **고치기:** `rrule`, `prompt` 수정은 다음 실행에 반영된다.
- **멈추기:** toml을 `PAUSED`로 고쳐도 **앱 DB에는 바로 반영되지 않는다.** 다른 자동화가 실행될 때 앱이 파일을 다시 읽어 반영하는 것으로 보인다(추측). 이미 DB에 `ACTIVE`로 들어간 자동화를 멈춘 뒤 바로 믿지 않는다. 확실히 멈추려면 폴더를 지운다.
- **지우기:** 폴더를 지우면 예약이 멈춘다. 앱 DB에는 row가 `ACTIVE`로 남는다.

## 확인하는 법

- 앱이 받아들였나: `codex-dev.db`의 `automations` table에서 row를 본다. **복사본을 읽는다**(앱이 쓰고 있다). 앱 DB에 쓰지 않는다.
- 돌았나: `~/.codex/state_5.sqlite`의 `threads` table에 제목이 `Automation: <name>`인 대화가 생겼나. 이 DB는 직접 열면 "unable to open"이 나서 복사해서 읽는다. heartbeat는 새 대화가 생기지 않고 대상 대화의 갱신 시각이 바뀐다.
- 끝까지 됐나: 대화 기록(`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`)의 마지막 답.
- 앱 로그: `~/Library/Logs/com.openai.codex/` (날짜 폴더는 UTC).
- `memory.md`는 앱이 만들지 않는다. 모델이 스스로 만들 때만 생긴다. 기록을 여기에 기대지 않는다.

## 시험하고 쓸 것

앱 종료·재시작·맥 잠자기 때 놓친 예약의 처리, `DAILY` 밖 규칙에서 heartbeat가 같은 대화에 붙는지, 잘못된 파일이 앱에 보이는 모양, 폴더 삭제 뒤 같은 id 재생성에 기대는 자동화를 만들 때는 아래 「시험하는 법」으로 먼저 확인한다. 매일 아침 도는 일이면 놓친 예약의 처리부터 시험한다.

## 시험하는 법

시험용 id는 한 접두어(예 `<이름>-test-`)로만 만들고, 시험이 끝나면 폴더를 지운다(`PAUSED`만으로는 앱 DB에 남은 `ACTIVE`가 돌 수 있다). 같은 분에 여러 개를 겹치지 않는다. 시험 prompt는 "아무 작업도 하지 말고 '테스트N'이라고만 보고한다"처럼 아무것도 바꾸지 않게 쓴다.
