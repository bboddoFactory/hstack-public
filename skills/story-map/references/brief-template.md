# 시안 요청서 템플릿 (`데이터 폴더(~/workspace/hstack/data/story-map/<이름>)/tasks/<작업 이름>/화면-<호출 이름>-요청서.md`)

예: `~/workspace/hstack/data/story-map/sample-shop/tasks/web-장바구니-쿠폰적용/화면-첫비교-요청서.md`

메인은 `<호출 이름>`을 실제 이름으로 채우고 요청서·시안·설명·실행 보고에 같은 이름을 쓴다. 같은 작업에서 다시 요청하면 `첫비교`, `수정비교`처럼 다른 이름을 정한다. 지정할 출력 경로가 이미 있으면 새 이름을 사용하며 기존 요청서와 결과는 덮어쓰지 않는다. 아래 실행 예시도 같은 이름으로 맞춘다.

```markdown
# 시안 요청: <무엇> (이미지 3장)

## 먼저 읽을 것

1. 제품 문서: <전체 경로>
2. 현재 작업 파일: <전체 경로와 이번에 적용할 화면 명세·조건>
3. 개인 작업 기준: <Hstack의 project-guide.md 전체 경로와 이번 화면에 적용할 항목·범위. 없으면 부재와 대신 읽을 근거>. 관련 팀·디자인 지침: <실제 경로>. 시각 규칙: <프로젝트의 DESIGN.md 전체 경로(hstack 기록 폴더 또는 팀 문서)>

기준은 읽기만 한다. 적용한 항목·충돌·미확인·갱신 제안(없으면 없음)을 최종 보고에 짧게 남긴다. 접근 불가도 알리고 개인 안내나 프로젝트 지침은 고치지 않는다.

<지금 화면이 무엇인지 한두 문장. 참고할 화면 이미지가 있으면 실제 경로를 적는다.>

이번에 더할 것은 하나다.

> <무엇을 더하나 한 문장>

이것을 화면에 넣는 방법을 구조가 서로 다른 시안 이미지 3장으로 그려라. 색만 바꾼 변형은 안 된다.

## 만들 것

- 이미지 생성 도구로 PNG 3장을 만들어 이 폴더에 `화면-<호출 이름>-a.png`, `화면-<호출 이름>-b.png`, `화면-<호출 이름>-c.png`로 저장한다(데스크톱 가로, 16:10 근처). 위에 지정한 화면 이미지가 있으면 참고 이미지로 쓴다.
- `화면-<호출 이름>-설명.md`에 시안마다 세 줄: 구조, 좋은 점, 약점. 기존 요청서·이미지·설명·보고는 덮어쓰지 않는다.
- 코드나 HTML은 만들지 않는다. 다른 파일은 건드리지 않는다.

## 화면에 들어갈 내용 (글자는 아래 그대로, 짧게)

## 지켜야 하는 것

## 넣지 않는 것

## 생김새 규칙

<프로젝트에 디자인 규칙 문서가 있으면 거기서 색, 글꼴, 선, 금지한 것을 옮긴다. 옮기기 전에 이번에 바꾸려는 방향과 부딪치는 규칙이 없는지 본다. 부딪치는 규칙은 옮기지 않고 사용자에게 짚는다.>

## 세 장이 서로 달라야 하는 방향 (참고. 더 좋은 구조가 있으면 바꿔도 된다)

- a:
- b:
- c:
```
