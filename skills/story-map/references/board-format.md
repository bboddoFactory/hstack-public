# 작업 보드 데이터 형식

새 기록의 `data/story-map/<프로젝트>/board.json`은 아래 형식을 쓴다. [작업 기록 기준](../../../docs/work-records.md)의 책임 분담이 원본이며 보드에는 명세·완료 기준·결정의 사본을 넣지 않는다.

```json
{
  "format": "task-board",
  "project": "제품 이름",
  "verbs": [
    { "name": "메모 쓰기", "about": "메모를 남기는 행동" },
    { "name": "메모 찾기", "about": "남긴 메모를 다시 찾는 행동" }
  ],
  "tasks": [
    {
      "name": "메모 저장 오류 수정",
      "path": "tasks/저장-오류/작업.md",
      "verb": "메모 쓰기",
      "state": "doing"
    },
    {
      "name": "검사 명령 복구",
      "path": "tasks/검사-명령/작업.md",
      "verb": null,
      "state": "todo"
    }
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `format` | 새 형식은 `task-board`. 없으면 아래의 기존 에픽 보드로 읽는다 |
| `project` | 화면에 보일 프로젝트 이름 |
| `verbs` | 사용자가 겪는 순서로 배치할 행동 열. `name`은 고유하고 `about`은 해당 행동의 설명이다 |
| `tasks[].path` | 프로젝트 기록 폴더 안의 작업 Markdown 상대 경로. 작업 한 건의 식별 기준이며 중복하지 않는다 |
| `tasks[].name` | 카드에 보일 짧은 작업 이름. 단순 기능명보다 조사·추가·수정·제거 등 확인할 결과가 드러나게 쓴다 |
| `tasks[].verb` | 주된 행동의 이름. 해당 행동을 정하기 어려우면 null로 두고 공통 열에서 본다 |
| `tasks[].state` | `todo` 후보 / `doing` 진행 중 / `done` 완료 / `cancelled` 취소 |

세로는 위 순서의 네 상태다. 가로는 `verbs`의 순서와 마지막 공통 열이다. 여러 행동에 걸쳐도 카드·작업·상태는 하나로 유지한다. 다른 관련 행동은 작업 파일의 범위에 적는다. 작업의 분류나 표시 이름이 달라져도 파일 경로를 자동으로 바꾸지 않는다.

메인은 작업 파일에 결과·근거·남은 조건을 먼저 남긴 뒤 여기의 상태를 맞춘다. 후보를 시작하며 새 에픽이나 작업 사본을 만들지 않는다. 완료는 합의한 작업 결과의 확인이고 현재 제품 기능 목록이 아니다. 영구 취소는 성공 완료와 구분해 기록을 보존한다.

화면은 읽기 전용이다. 카드 선택 시 지정 파일의 현재 내용을 읽고 같은 폴더의 근거를 따라갈 수 있게 한다. 없는 파일이나 읽기 실패는 오류로 보이며 다른 작업의 이전 내용을 대신 보여 주지 않는다. 잘못된 상태·미등록 행동·중복 경로를 조용히 다른 상태로 배치하지 않는다. `path`는 외부 URL이나 프로젝트 밖을 가리키지 않는다.

새 요청의 목적과 사용자 흐름에 필요한 행동만 만든다. 업무 단계별 열이나 빈 후보 틀을 채우려고 만들지 않는다. 기존 보드의 변환은 별도 이전 작업에서 확인하며 기존 에픽·칸을 일괄 일대일 치환하지 않는다.

## 기존 에픽 보드를 읽을 때

다음은 이미 작성된 프로젝트 기록의 형식이다. 기존 자료의 의미와 표시를 보존하기 위한 것이며 새 작업을 이 형식으로 만드는 지침은 아니다.

### 기존 현황판 데이터 형식 (`데이터 폴더(~/workspace/hstack/data/story-map/<이름>)/board.json`)

예: `~/workspace/hstack/data/story-map/sample-shop/board.json`

```json
{
  "project": "제품 이름",
  "rows": [ { 에픽 }, …, { "name": "후보" } ],
  "verbs": [ { "name": "동사", "about": "…", "log": [ … ], "cells": [ [ {칸}, … ], [ … ], … ] } ]
}
```

- `rows`는 위에서 아래로 내는 순서이고 마지막은 `후보`다.
- `verbs`는 사용자가 겪는 순서다. `verbs[].cells`는 `rows`와 같은 순서의 배열이다(빈 배열이면 그 에픽에서는 앞 에픽 그대로 쓴다는 뜻).

## 에픽

| 필드 | 담는 것 |
|---|---|
| `name` | 에픽 이름. 번호가 아니라 목적에서 따온 짧은 이름(예: `기록-화면`), 손대는 영역이 나뉘는 제품이면 영역을 앞에 붙인다(예: `web-장바구니-쿠폰적용`). 넘기는 글과 설계 폴더의 이름이 되므로 정한 뒤에는 바꾸지 않는다. 마지막은 `후보` |
| `goal` | 이 에픽이 끝나면 할 수 있게 되는 것. 한 문장 |
| `check` | 완료 정의. 에이전트가 직접 돌려 확인할 수 있는 절차 몇 줄 |
| `state` | `계획` / `하는 중` / `끝남` |
| `log` | 정한 날, 목적이나 완료 정의가 바뀐 날, 끝난 날 |

## 동사

| 필드 | 담는 것 |
|---|---|
| `name` | 사용자가 하는 일. 동사로 |
| `about` | 무엇을 하는 단계인가. 한 줄 |
| `log` | 생긴 맥락부터 |
| `cells` | 에픽마다 칸 배열 |

## 약속 (동사 밖)

동사에 속하지 않고 앱 전체에 걸린 성질은 `verbs` 맨 끝에 `"kind": "promise"`를 붙인 열 하나로 둔다. 이름은 `약속`. 나머지 형식은 동사와 같다(에픽마다 칸 배열).

```json
{ "name": "약속", "kind": "promise", "about": "동사 하나가 아니라 앱 전체에서 사용자에게 항상 지키는 것.", "log": [ … ], "cells": [ … ] }
```

현황판은 이 열을 맨 오른쪽에 세로 선으로 갈라 보여 준다.

## 칸

| 필드 | 담는 것 | 현황판에서 |
|---|---|---|
| `name` | 칸 이름. 짧게 | 맵에 보인다 |
| `state` | `done`(체크), `now`(지금 하는 곳), 없으면 아직 | 맵에 보인다 |
| `what` | 할 수 있게 되는 것 한 문장 | 누르면 정보 창 |
| `screen` | 화면 디자인 `필요` / `불필요` / `애매` | 누르면 정보 창 |
| `decided` | 정한 것과 그 이유(사용자가 말한 이유) | 누르면 정보 창 |
| `comps` | 시안 경로(`comps/<주제>/b.png`) | 누르면 정보 창 |
| `undecided` | 아직 정하지 않은 것 | 누르면 정보 창 |
| `log` | 생긴 맥락부터 바뀔 때마다 | 누르면 정보 창 |

## log

```json
"log": [
  { "date": "2026-09-28", "text": "아래 에픽 후보로 나옴" },
  { "date": "2026-10-03", "text": "기록-화면 목적에 맞춰 올림" }
]
```

동사·칸·에픽은 생기는 즉시 첫 줄(어떤 맥락에서 나왔나)을 적고, 옮기거나 바뀔 때마다 한 줄씩 덧붙인다.
