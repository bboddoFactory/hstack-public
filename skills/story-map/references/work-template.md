# 작업 파일을 시작하는 방법

위치는 `data/story-map/<프로젝트>/tasks/<작업 이름>/작업.md`다. 경로는 같은 작업을 이어 가는 기준이므로 후보를 시작하거나 표시 제목을 고친다고 복제하지 않는다. 상태는 보드에서 관리한다. 상세한 공통 책임은 [작업 기록 기준](../../../docs/work-records.md)을 따른다.

후보는 제목·기대하는 결과나 질문·나온 이유 정도로 시작한다. 아래 목차를 빈 채로 전부 만들지 않는다. 작업을 구체화하며 실제 필요한 내용을 늘린다.

```markdown
# 작업의 짧은 이름

## 목적과 현재 범위
사용자가 어떤 결과를 얻어야 하며 지금 어디까지 하기로 했는지 적는다.

## 사용자 동작·조건과 완료 기준
명세 확인: <날짜, 사용자가 확인한 범위. 확인 전이면 비워 둔다>
기대한 동작·지원 조건·실패와 보존 조건 중 관련 있는 것을 적는다.
무엇을 어떻게 확인하면 현재 합의를 충족하는지 적는다.
후보 수단: <대화·실험에서 나온 "어떻게". 없으면 이 줄을 두지 않는다>

## 현재 결정과 적용할 자료
채택한 설계의 핵심·현재 선택의 짧은 이유와 근거를 적는다.
지금 실행에 적용할 상세 문서·해당 절을 연결한다.
이전 관찰·미채택 후보·과거 보고가 현재 지침과 섞이지 않게 한다.

## 확인 결과와 남은 일
실제로 확인한 결과·근거 링크·미확인·다음에 이어갈 지점을 적는다.

## 관련 기록
상세 경과는 [작업 로그](log.md)에서 이어 읽는다. 실제 로그가 생긴 뒤 연결한다.
```

긴 이해·설계·구현·검증 보고는 같은 작업 폴더의 별도 파일로 두고 필요한 부분을 연결한다. 채택한 조건을 요약에서 생략했다고 폐기된 것으로 보지 않는다. 현재 범위나 완료 기준이 달라지면 다음 위임·실행 전에 본문·적용 자료와 필요한 전달을 맞춘다.

작업 파일에는 현재 합의와 결과를 유지하고, 변경 이유·시도·사용자 지적·미결 논의는 같은 폴더의 `log.md`에 시간순으로 덧붙인다. 로그는 기록할 일이 생길 때 만들며 빈 로그를 미리 만들지 않는다. 시각 형식·프로젝트 요약·기존 이력 보존은 공통 작업 기록 기준을 따른다.
