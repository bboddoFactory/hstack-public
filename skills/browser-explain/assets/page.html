알림 설계

주문 알림은 한 번만 보낸다

  • 알림은 주문 저장 뒤에 보낸다. 저장이 실패하면 알림도 가지 않는다.
  • 같은 주문은 알림이 한 번이다. 주문 번호로 중복을 거른다.
  • 재시도 간격은 미정이다. 실제 실패율을 본 뒤 정한다.

정할 것은 하나다: 중복을 어디서 거를까

중복 알림을 어디서 막을까

중복 알림은 같은 주문에 알림이 두 번 이상 가는 일이다. 재시도 때문에 생긴다.

안얻는 것잃는 것
보내기 전에 거른다알림을 보내기 전에 주문 번호를 조회한다 받는 사람에게 중복이 가지 않는다. 조회가 한 번 더 든다.
받는 쪽에서 거른다 보내는 쪽이 단순하다. 받는 쪽마다 같은 검사를 만든다.

권고: 보내기 전에 거른다. 받는 쪽이 여럿이라 한 곳에서 막는 편이 싸다.

정함 알림은 주문 저장 뒤에 보낸다.

미정 재시도 간격은 아직 고르지 않았다.

주문이 저장되면 알림 서버가 한 번만 보낸다

알림은 주문이 저장된 뒤에 한 번만 나간다

알림 시스템은 서버 둘과 저장소 하나로 이루어진다

알림이 늘면 조회도 같은 비율로 는다

명령은 코드로, 화면은 이미지로 보인다

알림을 다시 보내려면 explain build를 부른다. 긴 줄은 블록 안에서 옆으로 밀어 본다.

curl -X POST https://example.com/notify -H "content-type: application/json" -d '{"order": 1042, "retry": 0}'
