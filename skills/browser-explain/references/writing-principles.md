# 설명 글의 원칙

설명 페이지의 글과 구성을 정할 때 고르는 원칙이다. 모든 원칙을 매번 적용하지 않는다. "꺼낼 상황"이 지금 페이지에 해당하는 것을 고른다. 원칙끼리 반대로 당기면 페이지의 질문에 더 직접 답하는 쪽을 택한다.

구분은 basics의 기준을 따른다. 업계 표준은 표준 문서가 있는 것, 흔한 관행은 이름과 출처가 있는 것이다.

| 원칙 | 구분과 출처 | 뜻 | 꺼낼 상황 | 이 스킬에서는 |
|---|---|---|---|---|
| 결론 먼저 (Pyramid Principle) | 흔한 관행. Barbara Minto, *The Minto Pyramid Principle* | 답을 먼저 말하고, 그 아래에 근거를 묶어 둔다. 근거 묶음은 서로 겹치지 않고 빠짐없이 나눈다 | 페이지가 답이나 주장을 가질 때. 근거가 여러 갈래일 때 | 결론은 제목 바로 아래 요약 목록으로. 라벨과 상자 없이. 본문의 절은 결론을 받치는 근거 단위로 나눈다 |
| 요점 먼저 (BLUF, Bottom Line Up Front) | 흔한 관행. 미 육군 글쓰기 규정 AR 25-50 | 첫 문단에 요점과 읽는 사람이 할 일을 쓴다 | 읽는 사람이 무언가를 정하거나 해야 할 때 | 사용자가 정할 것은 요약 바로 아래에 짧은 비교(얻는 것, 잃는 것)와 권고로 |
| 쉬운 말 (Plain Language) | 업계 표준. ISO 24495-1:2023. 국내 참고: 국립국어원 「쉬운 공공언어 쓰기」 | 읽는 사람이 필요한 것을 찾고, 이해하고, 쓸 수 있게 쓴다. 문장은 완결되게, 전문어는 풀어서 | 모든 페이지 | 압축 메모 대신 주어와 서술어가 있는 문장. 전문 용어는 지우지 않고 짧은 뜻을 붙인다 |
| 그림과 글을 함께 (멀티미디어 원칙, Multimedia Principle) | 흔한 관행(실험 연구). Richard Mayer, *Multimedia Learning* | 사람은 글만 볼 때보다 그림과 글을 함께 볼 때 더 잘 이해한다 | 모든 설명 페이지. 글로 설명하고 싶어질 때 | 설명의 중심은 그림. 글은 그림을 읽게 돕는 만큼 |
| 그림을 글로 반복하지 않기 (중복 원칙, Redundancy Principle) | 흔한 관행(실험 연구). Mayer, 같은 책 | 그림이 이미 보여 주는 것을 긴 글로 다시 쓰면 이해가 떨어진다 | 그림 아래에 그림의 순서를 풀어 쓰려 할 때 | 그림 아래에는 그림이 보여 주지 않는 것만 짧게 |
| 제목이 주장, 그림이 증거 (Assertion-Evidence) | 흔한 관행. Michael Alley, *The Craft of Scientific Presentations* | 제목을 주제 이름이 아니라 주장 한 문장으로 쓰고, 그 아래 그림이 증거가 된다 | 그림이나 절마다 제목을 붙일 때 | 그림 제목은 "주문이 저장되면 알림 서버가 한 번만 보낸다"처럼. 부제는 그림 이름과 고른 이유 |
| 크기는 길이로 (그래프 지각 순위) | 흔한 관행(실험 연구). William Cleveland, Robert McGill, "Graphical Perception" (1984) | 사람은 위치와 길이로 크기를 가장 정확히 읽고, 넓이나 색으로는 덜 정확히 읽는다 | 숫자를 견줄 때 | 값의 비교는 막대. 여러 항목의 비교는 표. 원그래프나 색 농도로 크기를 보이지 않는다 |
| 설명은 그림 옆에 (공간 근접, Spatial Contiguity) | 흔한 관행(실험 연구). Richard Mayer, *Multimedia Learning* | 그림과 그 설명 글을 떨어뜨리지 않고 가까이 둔다 | 그림에 번호, 색, 기호를 붙일 때. 범례가 필요할 때 | 범례는 그림 바로 위나 옆. 번호 배지의 뜻은 그 그림 아래 번호 목록으로. 맨 위 기호 사전으로 몰지 않는다 |
| 필요 없는 것 빼기 (일관성, Coherence) | 흔한 관행(실험 연구). Mayer, 같은 책 | 질문에 답하는 데 쓰이지 않는 글, 장식, 배지는 이해를 방해한다 | 상태 배지, 면책 문구, 상자 테두리를 더하려 할 때 | 절마다 붙는 "확인하지 않았다"류 문구는 맨 아래 한곳에 모은다. 상자 속 상자를 만들지 않는다 |
| 핵심 표시 (신호, Signaling) | 흔한 관행(실험 연구). Mayer, 같은 책 | 무엇이 중요한지 굵기, 색, 제목으로 짚어 준다 | 그림이나 표에서 봐야 할 곳이 일부일 때 | 강조는 한 페이지에 몇 곳만. 모든 곳을 강조하면 아무 곳도 강조되지 않는다 |
| 앞에 두고 굵게 (F자 훑어 읽기) | 흔한 관행(시선 추적 연구). Nielsen Norman Group, "F-Shaped Pattern For Reading Web Content" | 화면의 글은 줄의 앞부분만 훑어 내려가며 읽는다. 핵심을 줄 앞에 두고 굵게 하면 훑어도 잡힌다 | 요약 목록, 긴 목록을 쓸 때 | 요약 항목마다 앞의 핵심 구절 하나를 굵게. 모든 곳을 굵게 하면 아무 곳도 눈에 띄지 않는다 |
| 나눠 놓지 않기 (주의 분산 효과, Split-Attention Effect) | 흔한 관행(실험 연구). John Sweller, 인지 부하 이론 | 함께 봐야 이해되는 정보가 두 곳에 나뉘면 이해가 떨어진다 | 설명 일부를 채팅에 두려 할 때. 다른 페이지를 열어야 이해되게 만들려 할 때 | 그림을 이해하는 데 필요한 설명은 페이지에 둔다. 채팅은 짚고 판단하는 곳이다 |
| 문서 종류를 섞지 않기 (Diátaxis) | 흔한 관행. Daniele Procida, diataxis.fr | 문서는 따라 하기, 방법, 참조, 설명 네 종류로 다르게 쓴다. 섞으면 어느 목적도 못 이룬다 | 많은 항목을 그대로 늘어놓으려 할 때 | 설명 페이지는 "왜, 어떻게 되나"를 답한다. 원자료 나열(참조)이 필요하면 결론과 그것을 받치는 대표 사례를 먼저 두고 전체 목록은 아래나 따로 둔다 |
| 정보를 전하지 않는 잉크 줄이기 (Data-Ink Ratio) | 흔한 관행. Edward Tufte, *The Visual Display of Quantitative Information* | 그림과 표에서 정보를 나르지 않는 선과 색을 줄인다 | 표 테두리, 배경색, 아이콘을 더할 때 | 색은 뜻이 있을 때만. 같은 색이 두 뜻을 갖지 않게 한다 |

## 표를 쓸지 정하는 기준 (내 의견)

표는 행과 열이 같은 기준으로 비교될 때 쓴다. 칸에는 짧은 값이나 구절이 들어간다. 다음이면 표 대신 글이나 목록으로 쓴다.

- 칸 하나에 문장이 두 개 넘게 들어간다.
- 열이 넷 넘어 좁은 화면에서 칸 폭이 몇 글자가 된다.
- 행마다 다른 기준으로 읽어야 한다.

## 실패 예 (가상)

| 실패 | 왜 못 읽나 | 고친 모양 |
|---|---|---|
| 시퀀스에 빨간 번호 1~5를 붙이고 범례에 "● 빈틈 후보"만 썼다 | 번호마다 무슨 빈틈인지 페이지에 없다. 만든 대화를 모르면 읽을 수 없다 | 그림 바로 아래에 "1. 알림 서버가 멈추면 주문 확인이 사용자에게 가지 않는다"처럼 번호 목록을 둔다 |
| 첫 문단이 "분류표: 대상 하나하나에 같은 기준을 대어…"로 시작하고 답은 맨 아래 한 문단에 있다 | 무엇을 알게 되는지 끝까지 읽어야 안다 | 제목 아래 요약에 "알림은 주문 저장 뒤에 보낸다", "저장이 실패하면 알림도 가지 않는다"를 목록으로 |
| 표의 노란 줄에 "→ 아래 결정 2"라고 썼지만 페이지에 결정 절이 없다 | 가리키는 대상이 대화에만 있다 | 결정할 내용과 선택지를 그 줄 아래나 페이지 안 한 절에 쓴다 |
| 세 후보의 시험 결과를 항목별로 모두 그대로 늘어놓았다 | 무엇을 보라는지, 그래서 어느 쪽이 나은지 없다 | 맨 위에 "어느 후보가 기준에 가장 맞나"의 답과 근거 서너 개, 결과가 갈린 대표 사례를 두고 전체 목록은 아래로 |
| "실행마다 한 행 추가 · 실패하면 행 없음" | 명사를 가운뎃점으로 이어 빠진 말을 읽는 사람이 채워야 한다 | "실행할 때마다 한 행을 더한다. 실패하면 행을 남기지 않는다." |
| 노란 칸을 범례에서는 "주의할 곳", 결론에서는 "실패한 곳"이라고 했다 | 같은 색이 두 뜻이라 무엇을 기준으로 칠했는지 모른다 | 한 색에 한 뜻. 두 구분이 필요하면 두 표시를 쓴다 |
