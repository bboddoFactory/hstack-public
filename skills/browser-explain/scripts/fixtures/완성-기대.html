제안한 구조, 아직 만들지 않았다

스킬 CLI가 생겨도 페이지 제작 에이전트는 남는다

  • 에이전트는 그대로 들어간다. 글과 그림 입력은 에이전트가 쓰고, 그리기와 넣기와 검사는 스킬 CLI 명령이 한다.
  • 그림마다 프로세스를 나누고 끊는 장치가 남는다. 스킬 CLI가 안에서 기존 그림 엔진 CLI를 부르기 때문이다.
  • 사용자는 허브 서버로 본다. 늘 켜져 있고 파일을 쓰지 않는다.

새로 생기는 것은 스킬 CLI와 허브 서버 둘이다

페이지 하나에서 에이전트는 글과 입력만 쓰고 나머지는 명령을 부른다

에이전트가 SVG를 읽고 넣는 일이 사라진다

일에이전트가 직접 하면제안한 구조에서
그림을 페이지에 넣기 넣는 스크립트를 페이지마다 새로 짠다. build가 한다.
그림 파일(SVG) 다루기 엔진 SVG는 한 장 8~26KB라 읽고 쓰면 토큰이 든다. 에이전트는 SVG를 읽거나 붙여 넣지 않는다. 엔진 결과는 수백 바이트, 검사 결과는 한 줄이다.

확인하지 못한 것

  • 그림을 페이지에 넣는 방식이 정해지지 않았다. 완성 페이지에 SVG를 그대로 넣거나, 페이지가 그림 파일을 img로 가리킬 수 있다. 한 번 만들어 iPad Safari에서 본 뒤 정하며, build가 하는 일이 이것에 따라 달라진다.
  • 허브가 새 자료를 사용자에게 알리는 방식이 정해지지 않았다. 허브가 몇 초마다 확인해 표시하는 안을 권고한다.
